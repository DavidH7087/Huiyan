# 慧眼 Phase 4C：PDF/DOCX 测试样本补全

日期：2026-11-14

用户反馈：现有 GitHub 仓库的简历样本偏重 TXT，且实际 PDF/DOCX 导入出现「无法识别文字」。这两件事需要分别解决，不能把生成样本当作修复导入问题。

## 本阶段实现

- 合成数据生成器现在为 120 位虚构候选人**每人生成 DOCX 和带文字层 PDF**，不再只抽取其中 24 人。
- 继续保留 12 份图像扫描 PDF，供 OCR 测试；20 个 ZIP 覆盖 6 类岗位 × TXT/Word/PDF，以及混合与重复文件。
- GitHub 仓库提供代表性 `.docx`、`.pdf`、扫描 `.pdf` 文件，完整批次由 `Huiyan Synthetic Corpus` 自动化工作流生成 ZIP。
- 完全虚构，无真实求职者联系方式，不要当作真人简历或自动招聘判断依据。

## 已完成的本地验证

- 120/120 DOCX 可以从 Word 正文及表格提取文字。
- 120/120 文字 PDF 可以提取文字。
- 已实际使用本地中文+英文 Tesseract 对扫描 PDF 抽样识别，检查来源标记与可读文本。
- Word 图像简历、Word 浮动文本框、PDF 扫描件、禁用 OCR 提示和坏文件均有回归测试。

## 限制

这仍不能证明上传的某一份**真实**简历可识别：扫描质量、OCR 语言包、PDF 加密与字体编码都可能影响识别。请在经过授权后使用脱敏样本或进一步检查实际文件。
