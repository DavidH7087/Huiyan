# 慧眼 Phase 4B · 合成简历压力与质量测试集

日期：2026-11-14。此阶段只生成**虚构**候选人数据及可复现的测试，不采集或传播真实简历。

## 已完成

- 共 120 位模拟候选人，覆盖企业 B2B 销售、Java 后端、Python 数据分析、财务、招聘及仓储库存管理六类岗位，每类 20 人。
- 120 TXT、24 Word DOCX（包含表格）、24 带文字层 PDF、12 图片扫描 PDF、8 ZIP（6 个岗位批次、1 个混合格式、1 个重复文件）、3 个故意无效文件。
- `jobs.json` 记录可直接复制到慧眼的岗位需求；`truth.json` 记录用于对照的预设标签与难例类型。
- 自带 deterministic 生成脚本、基准测试脚本、GitHub Actions 自动生成完整 ZIP 流程。
- 输出同时可用于批量导入、OCR 识别、结构化技能/学历提取、否定句匹配、源文件保留、去重、异常隔离及多轮筛选测试。

## 基线观察：旧版基础文字匹配引擎（合成集）

| 参考标签和预测组合 | 数量 |
|---|---:|
| 真正需要优先核实且被列入「优先查看」 | 60 |
| 参考标签为「需要确认」却被误列入「优先查看」 | 22 |
| 参考标签为「优先查看」却被列入「需要确认」 | 0 |
| 正确列入「需要确认」 | 38 |

合成样本上的“优先查看”查准率为 **73.2%**、查全率为 **100%**。这**绝对不表示真实招聘准确率或可用作淘汰决定**，因为标签由测试模板预设，样本的职业表达和长度都较简单，未经过独立人工标注。

已发现错误集中在：明确否定句、培训或课程含目标词汇、与岗位有关但未实际独立承担职责、信息不足等情况。典型问题包括 Java 与 SQL 只在课程中出现，以及财务候选人明确说“未从事财务核算”却被识别为符合。每个错误记录在 `benchmark/predictions.json`。

## 文件格式和 OCR 自检

- 120/120 TXT 可提取文字。
- 24/24 DOCX 可提取文字，表格有独立结构。
- 24/24 文字 PDF 可提取文字。
- 12/12 模拟扫描 PDF **不含 PDF 文字层**，需本地 OCR。
- 使用本地 Tesseract `chi_sim+eng` 对 12 张图片 PDF 实测，12/12 均识别出文本，但有标点、姓名等局部识别误差，未经逐字段准确率验收。必须人工核对原件。
- 手工查看了 Word、文字 PDF、模拟扫描 PDF 各一份的渲染图，均无明显截断。

## 使用限制与下一步

不能根据合成样本统计量宣称现实业务上线效果。推荐接下来把这 22 个误标作为独立回归任务，改善否定词作用域及岗位职责证据，并加入不同简历格式的真实授权脱敏样本做盲测。

仓库中的 120 份 TXT 不包含任何个人真实数据；大型二进制样本采用可复现脚本与 CI Artifact 交付，防止仓库被几百个重复格式文件污染。默认 `generated/` 路径不会提交到 Git。
