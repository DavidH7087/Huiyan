# 慧眼 v0.9.3-preview · 姓名与简历资料展示验收

## 本轮用户需求

1. 取消无法通过 localhost 正常打开的“打开原文件”功能。
2. 将简历提取结果整理成对 HR 更清楚的基础信息、年限、工作经历、学历、专业技能和原文展示。
3. 清理过长、重复、带括号说明、技术化或泛泛而谈的 UI 文案。
4. 从简历内容提取应聘人姓名，以姓名作为列表主标题，文件名仅在资料来源位置显示。

## 实现说明

- 新导入：从中文“姓名：张三”、有空格的“姓 名”、Word 表格“姓名 | 张三”、英文 Name/Full Name、简历页首独立姓名中读取。无法可靠识别时为“姓名待确认”，**不再把文件名当作姓名**。
- 历史简历：数据库添加 `name_source` 列，旧档案迁移后在查看旧任务时重新提取。已有非文件名的姓名保留；HR 手动修改的姓名永不自动覆盖。
- 人工纠错：候选人资料右侧“修改姓名”；更名后结果页、简历详情、Excel 导出和以后新建轮次使用同一保存结果。不会修改历史评估快照或审核备注。
- 原始文件：取消 UI 按钮和 `GET /api/tasks/{task_id}/resumes/{resume_id}/original`。**源文件本身不会删除**；仍保存在本地数据目录，用于加密备份和删除操作。
- 信息展示：独立简历详情页分区显示经历与年限、学历、专业技能和原文页码；折叠分页不再跳转浏览器。
- 文案：去除多余解释和非必要括号，采用招聘岗位、筛选条件、审核记录、姓名等企业场景用语。

## 验收与边界

- `tests/test_candidate_names.py` 检查中文及英文格式、Word 表格、未识别姓名、旧记录迁移、手动修正、跨任务权限、Excel 姓名以及原文件链接取消。
- Chromium E2E 测试以实际页面操作验证姓名编辑、结构化简历查看和无原文件链接。
- CI、OCR 与 Windows 基础版及 AI 版的安装器检查以本 PR 的 GitHub Actions 结果为准。
- **必须在用户 Windows 机器补测**：安装新版后原 5 份简历的姓名和详情、以前的审核备注和 5 轮筛选，尤其检查 PDF/Word 实际提取效果。本次 GitHub CI 使用合成资料。

### 实机简化复测

先备份本机招聘档案，再关闭原软件安装新版。打开旧任务，直接检查五人的姓名显示；如未识别，单击“修改姓名”并保存。点击“查看简历详情”，确认信息分区、全文与页码；检查不再出现“打开原文件”按钮。最后打开旧轮次并导出一次姓名列，确认历史记录没有变化。不需要重复早已通过的导入、Excel 文件保存等流程。
