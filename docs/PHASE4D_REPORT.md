# 慧眼 Phase 4D：修复 PDF / DOCX「无法识别文字」问题

日期：2026-11-14。基于用户真实使用中“简历无法识别文字”的反馈，但未取得那份实际简历；以下验证基于虚构的 PDF/DOCX 及可复现扫描件。

## 本阶段改变

1. OCR 改为本地运行时具备完整依赖时自动启用，不再默认关闭。
2. PDF 单页文字层为空、文字非常少或包含大量 Unicode 替换符时调用本地 OCR。
3. DOCX 增加表格、页眉页脚、浮动文本框读取；当 DOCX 没有足够文本且内含图片时，对有限数量的图片执行本地 OCR。
4. 文件完全无法读出文字时，返回“扫描件 / OCR 未就绪 / 文件损坏”等更有用的错误提示。
5. Windows 打包工作流增加本地 OCR 可执行文件、简体中文与英文语言包随包部署，并验证构建产物 `/api/health` 的 OCR 状态。
6. 扫描 PDF 和图片式 DOCX 的 OCR 文字始终带核对警告，不作为已经核实的任职资格。

## 本地实际检查

- 120/120 虚构 Word DOCX 文字提取成功。
- 120/120 带文本层 PDF 文字提取成功。
- 浮动文本框、页眉页脚和普通表格测试通过。
- 图像式 Word OCR、图像扫描 PDF OCR 以及禁用 OCR 时的清晰报错有回归测试。
- Windows 包含 OCR 的能力需要以本次提交后 GitHub Actions 的结果确认；源码测试与最终安装包验收是两种不同的验证。

## 已知限制

未得到用户那份失败的原始简历，无法确定是图片、加密、字体编码还是异常文件。Windows 正式发布仍需实机 UI 验收、离线断网测试、签名和企业数据保护评估。
