# 慧眼 · Phase 8 发布前质量强化报告

本阶段直接在现有仓库 `DavidH7087/Huiyan` 的 `main` 分支迭代。所有测试使用虚构简历，没有上传求职者个人信息。

## 已实现

1. **备份一致性**：先用 SQLite backup API 获取一致快照，再从快照中的 `resumes` 记录选择原文件；针对备份时并发插入及原件缺失新增测试。数据库与文件系统跨介质无法实现完全原子快照；若导入/删除使原文件在备份期间消失，系统报错而不宣称备份成功。
2. **打包 OCR 真识别**：Windows EXE 冒烟测试构建图片式、没有文字层的 PDF，用随包 Tesseract + PDFium 识别英文样本，不再只测试 `ocr.state=ready`。分别测试源码启动、便携版启动和安装后启动。
3. **240 份真实 API 导入**：合成测试工作流对 120 份 DOCX 与 120 份文字 PDF 分批调用 FastAPI 上传接口，验证 240 份导入、数据库记录、原件读取以及创建筛选轮次。与仅做文件解析单元测试不同。
4. **旧版本迁移**：使用旧数据库结构和虚构的已存档数据，验证新增筛选字段后，原招聘任务与候选人保持不变。
5. **单人数据删除**：输入完整原始文件名确认，从所有轮次删除该候选人评价、简历原件、审核历史及缓存；保留其他候选人，并留下不含身份信息的删除事件。历史候选人数因此可能变化。
6. **异常 DOCX 防护**：在 Word 解析前检查 ZIP 内部路径、加密标记、文件数量及总解压体积，拒绝异常压缩文档，减少简历导入时资源耗尽的风险。

## 尚不能认定正式商用完成

- 未在真实 Windows 11 用户桌面完成 WebView2 界面、卸载/升级、断网和长时稳定性人工验收。
- 未对来源多样的真实、合规脱敏简历做独立人工标注的准确率评估；模板合成测试的 100% 不代表真实招聘质量。
- 尚缺企业级身份权限模型、磁盘静态加密策略与个人信息保留/到期清理机制。删除不会自动撤销已经导出的加密备份或其他副本，也不是物理安全擦除。
- 商用代码签名、Windows Defender/SmartScreen 验收、软件与模型许可、品牌商标、隐私影响评估和业务责任仍需完成。
- 本仓库是公开源码，严禁提交真实个人简历或包含候选人资料的日志、截图与备份。

**结论：** 代码和 Windows 内部预览版进入更严格的质量验收阶段，尚未被批准为企业商用版。
