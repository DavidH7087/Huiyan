# 慧眼 v0.9.2-preview · 旧轮次参考条件清理

日期：2026-11-16

## 实机测试来源

用户用 Windows v0.9.1 在原 5 份虚构简历上创建第 4 轮，确认以下修复已经通过：
- 7 条重复文字证据压缩为 5 项独立能力
- 明确否定句不再被作为正向语义经历
- Python 后端开发不再误匹配客户开发
- “5年”岗位经验已正确识别

遗留问题：复用更旧的轮次时，系统照搬原始快照中的无效“招聘”参考条件，导致正向样本覆盖率为 83%。

## v0.9.2 的修复

1. 复用旧轮次将条件正规化、去重，并清理历史版本误从“招聘B2B销售”之类的招聘动作中提取的独立“招聘”条件。
2. 如果旧自动参考线索明确包含“招聘”，且当前岗位的必须条件已被 HR 修正，新轮次也会移除以前误生成的同名必须条件。
3. 对真正招聘专员的校园招聘经验等岗位能力予以保留；对当前仍由 HR 明确设为必须的“招聘”条件不自动删除。
4. 恢复旧轮次岗位条件采用同一清理规则，避免把失效线索带回当前任务配置。
5. `removed_legacy_terms` 保存在**新**轮次快照，页面明确提示清理了哪些旧条件。原四轮筛选、原评估和人工审核历史不重写、不删除。

## 回归验证

- `tests/test_legacy_round_replay_cleanup.py`：保留 4 个原始轮次，复用后产生第 5 个新轮次；对明确的 5 项文本证据，覆盖率 100%，原轮次前后原样保留。
- 另外验证招聘专员的真实招聘技能、用户明确指定的必须条件、以及旧条件恢复。
- GitHub PR #3 的 CI、浏览器 E2E、Windows 基础版和 AI 版构建是合并门槛。

## Windows 手工复测（无需重复已通过的导入、Excel 等项）

1. 先备份本地招聘档案并关闭慧眼，安装 v0.9.2 测试版。
2. 打开原 4 轮测试任务，在旧轮次点击“复用条件”。
3. 查看新建的第 5 轮：无效“招聘”项不再作为条件；结果页显示清理提示；5 项真实相关能力不重复。
4. 返回原 4 轮查看，确认它们的条件、人数和审核记录没有变化。
5. 仅在需要时测试“恢复条件”；不要把复用与恢复误认为自动修改旧档案。

**注意：**自动测试不代表已经在用户 Windows 设备上实际复测 v0.9.2，也不意味着系统有能力自动确认候选人胜任岗位。
