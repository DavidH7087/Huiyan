# 慧眼 v0.9.5-preview · 多条证据与科技行业经验

## 问题与根因

补充条件“需要科技领域的经验”时，旧版可能展示计算机科学课程，却没有展示靠后出现的 IT 与无人车产品实习。检查发现两个原因：

- 关键词检索只返回第一条文字证据，离线语义检索也只返回相似度最高的一条。
- 没有把“实际工作/实习”“项目”和“大学教育”分开，也没有明确的科技行业从业场景规则。

## 改动

1. 每个条件最多展示三段独立的文字证据，语义搜索最多保存三段待核实线索。**一项条件仍计数一次**。
2. 对“科技行业经验”“科技领域的经验”等要求，结合工作经历章节和行业关键词查找实习/任职，优先展示无人车、智能驾驶等领域，再列其他 IT 实习。
3. 单独显示项目背景和教育背景；计算机专业课程、嵌入式项目不会直接算成科技行业工作经验。
4. 每条证据均保留页码和“查看原文”入口，定位到已提取文本。Word 浮动文本框中的文字也参与检索。
5. 旧轮次的 `evidence`、`semantic_hint` 继续兼容；新轮次新增 `evidence_matches`、`semantic_hints`、`background_evidence`。不会自动重算既有轮次、修改人工审核记录、删除原始文件。
6. 如果 HR 显式选择“仅匹配原词”，不会额外使用行业场景推断或语义相似内容。

## 自动化检查

- `tests/test_multi_evidence_industry.py`：使用完全虚构的候选人和公司，模拟计算机科学教育背景、IT 实习、无人车科技公司实习、嵌入式项目和非科技工作；检查证据排序、分类、计数、精确匹配、语义多条候选和历史轮次稳定性。
- 上述文件程序化生成带浮动文本框的 DOCX，并从真实 Word 解析入口验证两段实习均被识别；**没有上传真实个人简历到 GitHub**。
- `tests/test_ui_browser.py`：真实浏览器验证行业工作经历、项目、教育分组和第二条证据的原文定位。
- GitHub CI、OCR、Windows 基础与 AI 安装包、240 份合成简历 Corpus 测试均是合并质量门槛。

## 安全边界及待验证问题

这里的行业分类仍然是保守的文本线索。它**不能证明候选人真实具有该领域经验**，也无法完整覆盖所有科技岗位、跨行业工作和混乱的 PDF 排版。不能因为教育背景不匹配自动排除候选人。未来需要真实、合法脱敏且人工标注的跨行业样本评估精度与召回率。

## 推荐实机验收

在 Windows v0.9.5 AI 版中保留已有岗位和历史筛选记录，新增一轮补充条件“需要科技领域的经验”。检查：
1. 实习/工作经历优先显示无人车科技企业，其次其他 IT 产品实习；
2. 项目和大学计算机课程分别展示在辅助背景，未被当作行业任职经验；
3. 同一条件显示多条证据，但条件数只计一次；每条“查看原文”均能定位相应内容；
4. 旧轮次、审核状态和 Excel 记录原样保留，不需重复已经通过的导入/导出测试。
